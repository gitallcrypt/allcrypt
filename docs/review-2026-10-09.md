# Code review, October 2026

A code-quality and design review of the whole tree, carried out on
2026-10-09, and the fixes that followed it. It is kept here because what
was found, what was changed and what was left are worth being able to
read, not only the code they produced.

Weak and obsolete algorithms were out of scope: implementing them
correctly is the purpose of the library. The review looked at
correctness, robustness against untrusted input, API design, and the
invariants [the extension guide](extending.md) and [the pitfalls list](pitfalls.md) set out.

## Outcome

| Severity | Found | Fixed | Not fixed |
| --- | --- | --- | --- |
| High | 15 | 15 | 0 |
| Medium | 60 | 58 | 2 |
| Low | 98 | 85 | 13 (3 accepted, 1 declined, 9 left) |

Four further defects were found while fixing and are fixed too (listed
below). Every fix was made separately, with a regression test that
fails on the code before it and a note of how the existing tests missed
it.

The gate after the last fix: `cargo test` 2407 passed (2219 before),
`cargo clippy --all-targets` silent, `pytest` 3509 passed and 4 skipped
(five failures before, all fixed), and `check_docs.py`,
`check_c_api.py` and `check_messages.py` clean.

**Severity key.** High: wrong output, memory unsafety, a panic on peer-
or file-supplied bytes in a network or file path, or a security property
the code claimed and did not have. Medium: a design or API flaw, a panic
on library misuse, resource exhaustion, or drift between duplicates.
Low: quality, stale documentation, dead code, tests that cannot fail.

**Method.** The tree was read in full, area by area, not sampled, with
the project's own invariants as the standard. Every High and every
Medium was confirmed against the source before it was recorded; eleven
of the panics were reproduced with standalone `rustc -O` programs.
`cargo build`, `cargo clippy --all-targets` and `cargo test` were clean
on the tree reviewed, so nothing here is something the gate already
caught.

### Found while fixing

- TLS 1.3 server hashed the second ClientHello twice after a HelloRetryRequest, so every retry it sent failed at the first encrypted record; the existing retry test never produced a retry.
- A `.example.com` URI or mail constraint admitted `evilexample.com`: the leading-period form did not stop at a label boundary.
- `allcrypt_ssl` lacked Python 3.13's `HAS_PSK`, failing the name-for-name drop-in test.
- Four `test_private_key.py` tests failed on python-cryptography 50.0, whose `Encoding` has no `.name`.

## What was left, and why

- **Constructor and IV signatures (S7).** Thirteen ciphers take
  `Vec<u8>`, eight take `&[u8]`, and the trait mixes both for IVs.
  Unifying them is mechanical but reaches the SSH, TLS, KDF and X.509
  modules, eleven product examples, five tools and the documentation, so
  the shape is a decision to take first.
- **Shared helpers in the examples (E10).** About thirteen copies each
  of `hex`, `unhex`, `positional` and their kin. No defect today.
- **The key-size ceiling as a `Policy` field (X3).** The 16384-bit
  ceiling is enforced, as `Policy::MAX_KEY_BITS`; making it configurable
  is a field on `Policy` plus a Python keyword.
- **The rest of the bindings' reach-through (B3).** `register_oid`'s
  curve parsing, the `Prng` imports and `ReplayGuard` in `python.rs`
  still use crate modules directly rather than `api.rs`.
- **Windows trust store (X.509/SSH L10).** The fix is `cfg(windows)` and
  has not yet been compiled on Windows.
- **Not yet measured.** `scripts/ct_check.py` has no rows for OCB, LRW,
  MGM, ACPKM or the MAC-then-encrypt record path, whose constant-time
  behaviour the fixes changed; the fixes keep the output byte-identical,
  but the timing claim is asserted rather than measured until those rows
  exist. The release build with `aes-ni,sha-ni,simd` was not rerun.
  The table that does exist passes, all 45 rows: three rows had been
  failing on this toolchain before the review and after it alike,
  because rustc 1.97 spells methods in the v0 demangling and the table
  in the legacy one; `scripts/ct_check.py` now matches either.

## High

All fifteen were confirmed in the source; the ones marked *(repro)* were also executed. Every one is fixed; see the status table above.

### TLS

1. **`require_client_certificate` is bypassed at TLS 1.2 by omitting the Certificate message.** `src/tls/server.rs:1056-1078, 1650-1708`. `WaitClientKeyExchange` accepts a `ClientKeyExchange` directly and the requirement is only checked inside `handle_client_certificate_12`, so a client that sends ClientKeyExchange, CCS, Finished and no Certificate completes the handshake with `peer_certificates()` empty. The 1.3 path is correct. Fix: a `WaitClientCertificate12` state after a CertificateRequest that accepts only `Certificate`, or refuse in `handle_client_key_exchange` when a request went out and no chain arrived.

### X.509 and SSH

2. **Name-constraint bypass through the CN fallback.** `src/x509/name_constraints.rs:408-440` folds the CN into the dNSName check only when `subject_alt_names.is_empty()`; `verify.rs:982-993` falls back to the CN whenever there are no *dNSName* entries. A constrained CA's leaf with `SAN=[rfc822Name]` and `CN=evil.test` passes the constraint vacuously and matches `evil.test`. This is the exact hole the project's notes said was closed; the test only covers the empty-SAN case. Fix: one shared `honours_cn(cert)` predicate used by both.
3. **A v1/v2 intermediate with no basicConstraints is accepted as a CA.** `src/x509/verify.rs:622-632`: `None => if issuer.version == 3 && !is_trust_anchor { Err }`. Any v1 end-entity certificate ever issued by a trusted root can therefore sign leaves for any name. Fix: `if !is_trust_anchor { Err }`, version-independent.
4. **SSH client loops forever on `maximum packet size = 0`.** `src/ssh/client.rs:414, 760-772`: `room` becomes 0, the loop emits empty CHANNEL_DATA packets without bound and `outgoing` grows until memory runs out. The server side already guards this with `.max(1)` (`server.rs:876`). Fix: the same guard, and bail when `room == 0`.
5. **Panic on a non-ASCII hostname in wildcard matching** *(repro)*. `src/x509/verify.rs:1042-1047` slices a `&str` at byte offsets taken from the peer's SAN pattern; `a*.example.test` against `é.example.test` panics on a char boundary. Reachable from the TLS client and Python with the certificate supplied by the peer. Fix: compare on `as_bytes()`, or refuse non-ASCII hostnames up front. `name_constraints::dns_matches/host_matches` (`:228-251`) have the same slice.

### Symmetric

6. **ChaCha with a 12-byte nonce wraps its 32-bit counter and repeats keystream.** `src/stream_ciphers/chacha.rs:106-111` carries into word 13 only for the 8-byte-nonce form; `chacha20poly1305.rs:144` checks only `u64` overflow of the byte count. After 2^32 blocks (256 GiB) the state equals the initial state and the tag still verifies. GCM (`MAX_TEXT_LEN`) and Salsa20 (`exhausted`) enforce their limits; this one does not. Fix: refuse past `2^32 - 1` blocks in `ChaCha20Poly1305::apply` and record exhaustion in `Chacha`.

### Hashes and KDFs

7. **`phpass` / `phpass_verify` panic on a stored hash with a multi-byte character** *(repro)*. `src/kdf/app_passwords.rs:187, 197`: `&setting[..12]` after a byte-length check only. Input is a password-dump row; exported to Python. Fix: `get(..12)` or require an ASCII salt.

### Shim (`libssl.so`)

8. **`SSL_write` re-encrypts and re-queues the same bytes after `WANT_WRITE`.** `shim/src/lib.rs:1541-1571`: `client.write(payload)` always encrypts into `outgoing` before `flush`; on a blocked write the shim returns `-1`/`WANT_WRITE`, and the program's mandated retry encrypts the chunk a second time. libcurl uploads under backpressure send data twice. Fix: remember the pending length; if `outbox` drains on retry, return it without calling `write` again.
9. **Integrity failures and bare TCP EOF are reported as a clean close.** `shim/src/lib.rs:1462-1481`: `ClientConnection::process` returns `Ok` for close_notify (`tls/client.rs:1236`), so its `Err` branch is only ever a bad MAC, decode error or fatal alert, and the shim maps all of those (and `read == 0` without close_notify) to `SSL_ERROR_ZERO_RETURN`. A truncated or tampered response reads as a complete download in curl/wget. Fix: `SSL_ERROR_SSL` on `Err`, and on EOF when `state != Closed`.
10. **`SSL_CTX_up_ref` / `SSL_up_ref` do not count references, so the documented second free is a double free.** `shim/src/lib.rs:310-321, 900`: `up_ref` leaks a clone box at a different address and returns 1; `SSL_CTX_free`/`SSL_free` unconditionally `Box::from_raw` the pointer passed. Fix: an `AtomicUsize` in the handle; free drops at zero.

### Product examples

11. **7z: `unpack_folder` indexes `pack_sizes` with counts no header check bounded** *(repro)*. `examples/products/sevenzip/archive.rs:359-372`; a header with no PackInfo panics from `open()` before any password or CRC. Fix: require `sum(folder.packed.len()) <= pack_sizes.len()` in `streams()`; `checked_add` on the offsets.
12. **PDF: an xref offset past EOF panics in `Parser::token`** *(repro)*. `examples/products/pdf/object.rs:120-128` with callers at `file.rs:118, 149, 183, 243` (`startxref`, `/Prev`, `/XRefStm`, every xref entry; a negative `/Prev` becomes a huge offset after `as usize`). Fix: `Err` when `at > data.len()`; reject negatives before the cast.
13. **PDF: a `/Length N 0 R` that refers to its own object recurses without bound.** `examples/products/pdf/file.rs:240-258`; same for an ObjStm whose xref entry says it lives inside itself. `/Prev` loops are guarded (`:123`); these two are not. Fix: an in-progress set threaded through `raw()`.
14. **OpenPGP: a v6 PKESK with a 2..8-byte key-id field underflows `fingerprint.len() - 8`** *(repro)*. `examples/products/openpgp/pubkey.rs:286-294`, run on every PKESK before any key is tried. Fix: require `n == 21` (v4) or `n == 33` (v5/v6) in `Pkesk::parse`.
15. **LUKS2: `hdr_size` from the header sizes the buffer that the checksum is computed over** *(repro)*. `examples/products/luks/main.rs:548-561`: `hdr_size < 512` panics at `copy[448..512]`; `512..4096` passes a checksum the attacker can fix and panics at `whole[4096..]`. Fix: refuse `hdr_size <= 4096` (cryptsetup allows only 16 KiB..4 MiB) before reading.

ZIP `(offset + size) as usize` unchecked. Office agile `hashSize` not checked against the hash. Key material in long-lived/`Debug` types. OpenPGP ignores trailing bytes after MPIs and stops at the first candidate key. CFB directory recursion bounded only by entry count. Smart card: `61 xx` forever loops. `shared/fixtures.rs::expand` trusts the sparse image's offsets.

## Patterns

Most of the list above comes from five habits, each of which one fix-the-class pass would remove.

1. **A length or offset read from the input is used before it is bounded.** Nine of the fifteen Highs and about a third of the Mediums are this shape: `pack_sizes[..n]`, `Parser::new(data, startxref)`, `fingerprint.len() - 8`, `read_at(image, hdr_size)`, `remote_max_packet = 0`, `&str[..12]`, `vec![0; 128*r*N]`. The core library mostly does this right (`codec.rs`, `asn1`, the record layers were clean); the examples and the KDF/password parsers do not, because they were written to read well-formed files from real products and `cargo test` only ever hands them those. A fuzz target per container format (`cargo-fuzz` on `open()` with no password) would find every one of these in minutes and is cheaper than the breakage sweeps already in use.
2. **Two siblings that should share one function and have drifted.** `names_of` vs `matches_hostname` (High #2), SSH server vs client on `max_packet` (High #4), `rsa.rs` vs `elgamal.rs` unpadder (P1), `Ticket::encode` vs `decode` (T7), three copies of `tls_selection` (B9), `ocsp::hash_oid` vs `builder::hash_oid` (X7), thirteen copies of `hex`/`unhex` in the examples (E10). The project already argues this case for `strips_leading_zeros` and `tls13_hash_name`; the same argument applies to each pair here.
3. **`#[derive(Debug)]` on a type that holds a secret.** `RsaPrivateKey`, `x509::PrivateKey`, `DirectionKeys`/`KeyBlock`, `Argon2`, `blake2::Params`. In each case a sibling in the same module hand-writes a redacting `Debug` with a comment saying why. A `#[deny]`-style check is not available for this, but `grep -n 'derive(.*Debug' | grep -i 'private\|key\|secret'` is a thirty-second gate step.
4. **A contract stated in a comment or in `docs/pitfalls.md` that the code beside it does not keep.** The Lucky 13 fixed-length MAC (T3), "SAN wins over CN absolutely" (X8), "this is the constant-time path" on GOST signing (P4), `cbcmac_calc`'s CCM (S1), the shim's "reported before the first handshake" (B5), the EAX streaming claim, the Whirlpool and TLS 1.0 comments. A comment that claims a check the code does not do is worse than none; these were the instances.
5. **The TLS 1.2 server state machine lets a message through on the strength of its type alone.** High #1 and T1 are the same gap from two sides: `WaitClientKeyExchange` accepts both `Certificate` and `ClientKeyExchange` whether or not a request went out. The 1.3 path separates the states and is correct; the 1.2 path needs the same `WaitClientCertificate12` state, after which both findings close with one change.

## Checked and found sound

Listed so the owner need not re-derive them, and so the Highs are read in proportion. Each item was traced by a reviewer who read the whole file, and the arithmetic was hand-checked.

- **Bignum and curves.** Knuth D bounds and `u128` ranges; both `mod_inverse` paths; CIOS bound `a*b < nR` in `to_domain`/`mul_mod`/`reduce_wide`; `pow_ct` window and masked table read; `ec::fixed` select polarity and SOS carry chain; `field25519`/`field448` limb bounds, inversion chains and the three-carry `to_bytes`; both Montgomery ladders; Jacobian and Edwards formulas for `a = ±1`; signed-digit recoding; `Order::reduce`; RFC 6979; ECDSA `r`/`s` checks; X25519/X448 clamping and low-order refusal; ML-KEM decode and FO select; ML-DSA Decompose/HintBitUnpack; SLH-DSA `base_2b` and FORS indices; sntrup encoders; RSA Bellcore check in fixed width, OAEP/PSS bounds, whole-block PKCS#1 compare.
- **Symmetric.** `modes.rs` partial-block handling and the state/borrow split; GCM/GHASH; XTS; CCM; OCB; Poly1305; UMAC; every `unsafe` block in `aes_ni.rs`, `chacha_simd.rs` and `sha_ni.rs` states its invariant and upholds it.
- **Hashes.** All eighteen hashes have a non-destructive `digest()` with `update` allowed after; `BlockBuffer` is correct and used correctly where it is used; HMAC is generic over `block_size()` (MD2's 16 is fine); PEM base64 padding is strict; `random` never falls back.
- **TLS.** `codec.rs` checks every length and never allocates from an untrusted one; record size limits enforced before allocation; sequence numbers `checked_add`; ETM MAC checked before decryption; the padding scan is a fixed window with one alert; `record13` header-as-AAD, nonce XOR, peek-and-commit counter; 64 KB reassembly cap; `decrypt_premaster` matches its documented description exactly (fallback drawn first, one mask, no early return, `legacy_version` compared); `keys.rs`/`keys13.rs` label and transcript rules; FREAK handling; SKE signature coverage; binder sliced not re-encoded; PSK placed last; early data bound to identity 0; tickets issued after Finished and kept out of the transcript; server Finished verified before `Established`.
- **X.509 and SSH.** DER long-form lengths, minimal INTEGERs, BIT STRING unused bits, depth limit; UTCTime pivot; chain building with loop detection and the shortest-trusted-prefix rule; `certificateIssuer` carry-forward in CRLs; OCSP signature before nonce, delegated-responder double check; SSH packet/mpint bounds, MAC-before-decrypt for ETM, KEX hash ordering, window arithmetic.
- **Bindings.** `python.rs` holds no borrow into Python memory across `allow_threads`; `Bytes` copies and checks contiguity; `capi.rs` null-checks, `catch_unwind` everywhere, header matches 67-for-67; the proxy has no verify-nothing switch; the shim honours `SSL_get_verify_result` and the `deny(unwrap)` lint.
- **Examples.** Every product example tests against fixtures written by the real product, with asserted counts; no corpus generator in `tools/` can emit zero rows silently.
